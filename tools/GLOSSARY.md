# 片库维护工具（tools）

用标准库写的一次性/巡检脚本，负责核对「网盘片库」「影片详情服务」「播放列表」三者是否一致。
它们不参与 App 构建，也不被 App 调用；本文件只收这个上下文的词汇。

## Language

### 片库与网盘

**番号**（fan_code）:
一部影片在片库里的唯一身份，就是媒体根目录下的一个一级目录名；所有跨源比对都以番号为准。
_Avoid_: 片名, movie_id, slug, 目录名（泛指）

**影片目录**:
媒体根目录下、含 `playlist.m3u8` 的那个一级目录。一个番号对应一个影片目录；没有 `playlist.m3u8` 的目录不是影片目录。
_Avoid_: 番号目录, 影片文件夹, movie folder

**媒体根目录**（media root）:
存放全部影片目录的固定网盘路径（`--media-root`），与 App 的 app 名对齐。
_Avoid_: 片库根, 根路径, root

**巡检方向**:
一次巡检是拿哪个源去比哪个源：网盘→详情服务、详情服务→网盘、播放列表→目录。方向决定「缺失」指的是什么。
_Avoid_: 正查/反查, 检查类型

**只读巡检**:
不写网盘、不改详情服务的巡检。写操作只有两处：`calc_media_size.py` 回写 `meta.json`、`find_missing_netdisk_movies.py --delete` 删记录。
_Avoid_: 安全模式, dry-run（那是单轮的「不上传」）

### 播放列表与分片

**播放列表**（playlist）:
影片目录里的 `playlist.m3u8`，单层 media playlist，里面直接列分片名。它是「这部片该有哪些分片」的唯一依据。
_Avoid_: m3u8 文件, 索引, manifest, 清单

**分片**（segment）:
播放列表列出的一个媒体片段（本项目是 `seg_<数字>.ts`）。
_Avoid_: chunk, 切片, part, ts 文件

**分片名**:
分片在播放列表里的写法：去掉 `?query`、取 basename 之后的那个字符串，比对用的就是它。
_Avoid_: 路径, 相对路径, URL

**分片号**（slug）:
分片名的归一形式（`seg_001023.ts` → `1023`）；认不出的命名原样当分片号。只影响怎么报给人看，不影响怎么比对。
_Avoid_: 序号, index, segment id

**精确同名**:
分片名与目录文件名的比对规则：不做 NFKC、不改大小写、不剥前后缀。宁可多报一条，也不把两个不同的名字并成一个。
_Avoid_: 模糊匹配, 容错匹配, 忽略大小写（那只是筛选词的规则）

**孤儿分片**:
在影片目录里存在、但播放列表没有列出的分片。巡检不报它 —— 播放只认播放列表，多出来的东西不咬人。
_Avoid_: 多余分片, 未使用分片

### 缺片的判定

**缺片**:
播放列表列了、影片目录里没有的名字（精确同名）。方向只有这一个，孤儿分片不算缺片。
_Avoid_: 分片丢失, 漏片, 缺失文件

**无法检查**:
有播放列表，但结论做不出来（master playlist、内容不是 m3u8、没有分片行）。这是数据本身的问题，重跑一万次也一样，不算缺片。
_Avoid_: 未知, 跳过, 异常

**处理失败**:
请求本身没成功（网络/HTTP/解析，重试耗尽也不算结论）。结论未知，重跑即可，不属于缺片。
_Avoid_: 失败, 错误（两者裸用都会与「结论是缺片」混）

**待办清单**:
巡检产出的 CSV（默认落在 `report.csv`）：只含需要动手的番号行，无缺片的不占行，行序恒为番号升序（两次结果可以直接 diff）。
_Avoid_: 报告（那是含全部行的清册）, 结果表

**结论**（outcome）:
单部影片在一轮里的判定结果（`ok` / `missing` / `severe` / `not_movie` / `not_inspectable` / `error`），汇总按它计数。
_Avoid_: 状态（裸用）, 结果

**判定**（verdict）:
待办清单每行的动作：`patch`（补列出的分片）/ `redownload`（建议整片重下，不给分片清单）。它不是结论 —— 结论是「这部片怎么样」，判定是「你该干什么」。
_Avoid_: status, 状态, action

### 严重缺片与阈值

**PCT**:
百分数的书写形式，也是比例模式的值：`--severe-threshold 30%` 里的 `30%` 就是一个 PCT（`30` 不带 % 则是片数）。PCT 取 `0%` 表示**关闭**阈值，不是「全都算」。
_Avoid_: percent, 百分比（裸用）, ‰

**缺失率**:
缺片的分片名数 / 播放列表的分片名总数，两边都按名字去重；绝对 URL 行两边都不算（无从比对）。
_Avoid_: 丢片率, 比率（裸用）

**阈值**:
`--severe-threshold` 给的那个值，看有没有 `%` 决定模式：`30%` 是比例阈值，`50` 是数量阈值（缺 50 片）。默认 `50`（数量）；判定是「≥ 阈值」，恰好等于就算达到；两个模式一次只生效一个，不是 OR。
_Avoid_: 临界值, 上限

**数量阈值**:
以「缺多少片」而不是「缺多少百分比」写的阈值。数的是去重后的缺片文件名数，不是 slug 数（slug 会把 `seg_1` / `seg_01` 并成一个）。
_Avoid_: 绝对阈值, 片数上限

**严重缺片**（severe）:
达到阈值（比例或数量，二选一）的片子。结论是下载本身出了问题，补几个分片救不回来，因此不给补片清单，只建议整片重下。
_Avoid_: 大量缺失, 下载失败, 坏片

**建议整片重下**（`verdict=redownload`）:
严重缺片对应的动作：整部影片重新下载，而不是补个别分片。
_Avoid_: 重新上传, 重转码

**同一批**:
播放列表与目录里的分片是否出自同一次转码/上传。100% 缺失时更常见的解释是「不是同一批」（重转码、改名、半截上传），而不是下载丢了。
_Avoid_: 同版本, 一致

### 一轮巡检与报告

**一轮**（run）:
一次完整调用：一套参数、一份全量结论。`--limit` 只是缩小本轮覆盖范围，仍是完整的一轮。
_Avoid_: 批次（那是详情服务一次请求里的番号集合）, 任务, session

**覆盖范围**:
本轮实际检查了多少部（`--only` / `--exclude` / `--limit` 的结果）。覆盖不全的「干净」不等于片库干净。
_Avoid_: 进度, 范围（裸用）

**检查顺序**:
`--sort` 决定先检查谁。它不影响覆盖范围，也不影响行序。
_Avoid_: 排序（说 CSV 时是「行序」）

**行序**:
CSV 里行的顺序，恒为番号升序；稳定行序是为了两次结果能直接 diff。
_Avoid_: 排序

**部分结果**:
中断/令牌失效时写出的半轮 CSV，文件名带 `.partial-<时间戳>`，绝不占用目标路径 —— 半张表不能冒充跑完的那一轮。
_Avoid_: 半成品, 草稿, 临时表

**不覆盖**（归档轮转）:
报告类产出的写入口径：内容逐字节相同就不写也不轮转；有变化才把旧文件归档成 `<stem>.<旧文件mtime>.csv`，再写新的；归档失败就中止、原文件不动。
_Avoid_: 追加, 合并, 直接覆盖

**筛选词**（term）:
`--only` / `--exclude` 的一个取值：不含 `*` `?` `[` 时按子串命中，含通配符时按 glob **整名**匹配，两种都忽略大小写。
_Avoid_: 关键词, pattern, filter

**复核**:
对单个或一小批番号重跑一遍（`--only`），用来确认可疑行；它不是另一种巡检。
_Avoid_: 抽查, 二次检查

### 影片详情服务（movie_api）

**完全缺失**:
详情服务里根本没有这个番号的记录。
_Avoid_: 无记录, 缺失（裸用）

**字段缺失**:
记录存在，但必填字段是空的（例如没有 title）。
_Avoid_: 信息不全, 缺字段

**必填字段**:
`--require` 指定的那些字段，默认 `title`。批量模式查不了 `description`，要查得用逐条模式。
_Avoid_: 校验字段, 必填项

**查询失败**:
这批请求本身没成功，整批结论未知 —— 不算缺失，重跑即可。
_Avoid_: 失败, 错误（裸用）

**批**（batch）:
一次请求里带上的一批番号（默认 30 个）。批内失败会连带整批结论未知。
_Avoid_: 分组, chunk

**逐条复核**（detail 模式）:
一部片一个请求地打详情接口，慢但能查任意字段（含 `description`）。
_Avoid_: 单条模式, 精确模式

**孤儿记录**:
详情服务里有、网盘里没有同名番号目录的影片记录。目录存在但缺 `playlist.m3u8` / `meta.json` 不算孤儿。
_Avoid_: 多余记录, 脏数据

**近似匹配**（near-miss）:
与番号只差首尾空白的网盘目录名；只告警，不当缺失（大概率是真匹配）。
_Avoid_: 模糊匹配（那是禁止的）, 近似番号

### meta.json 与清册

**meta.json**:
写在每个影片目录里的体积/时长元数据（schema_version = 2），由 `calc_media_size.py` 维护。
_Avoid_: 元数据文件, config, sidecar

**权威字段**:
`meta.json` 里唯一被当作事实的字段：体积 `size_bytes`、时长 `duration_seconds`；`*_human` 只是给人看的。
_Avoid_: 主字段, canonical 字段

**无法确定**:
时长算不出来时的有效结论（`duration_seconds: null`）。「键在、值是 null」是终态，不该被反复重算。
_Avoid_: 缺失, 未知（会让人以为是没算过）

**完整性**:
`meta.json` 是否已经够用（schema 正确、`size_bytes` 为正、时长键存在）。够用的就跳过 —— 这就是断点续跑。
_Avoid_: 有效性, 正确性

**清册**（inventory）:
每部影片一行、含全部番号的 CSV（`--report`），与「待办清单」正好相反。
_Avoid_: 报告（裸用）, 报表

### 访问与重试

**access_token**:
百度网盘调用的凭据，手动提供、手动更新；过期只在被拒时发现，没有自动刷新。
_Avoid_: 密钥, 凭证, cookie

**结论 vs 抖动**:
重试只对抖动（超时/连接失败/429/5xx）做；其余 4xx 是确定性结论，不重试。重试耗尽是「结论未知」，从不等于「缺失」。
_Avoid_: 异常, 偶发错误

**翻页收全**:
网盘列表 1000/页、详情服务 100/页，必须翻到总数收齐；只翻一半得到的缺失清单是错的。
_Avoid_: 分页（裸用）, 增量拉取

**直链**（dlink）:
由 `fs_id` 换发出来的分片下载地址；下载时要用 `pan.baidu.com` 的 UA。
_Avoid_: 下载链接, URL

**fs_id**:
网盘给单个文件的数字 ID；播放列表与分片都靠它换直链。
_Avoid_: file id, fsid, inode
